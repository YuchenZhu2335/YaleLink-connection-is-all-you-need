# RFC：先写一页，再动手

**什么时候需要**：新增模块；改动核心层（`web/js/core/`、`scripts/`、`.github/`）；改变已有的数据契约（字段、接口、状态机）。
文案、样式、修 bug、补内容这类小改动不需要。

**流程**

1. 复制下面的模板为 `docs/rfcs/NNNN-<名字>.md`，开 PR，标题以 `[RFC]` 开头；
2. 在 PR 或会上讨论，"待决问题"逐条拍板，结论写回文档；
3. 维护者批准合并 = 状态改为"已接受"，之后照着做。开发中发现要改规则，先改 RFC 再改代码。

## 模板

```markdown
# NNNN 标题

- 状态：讨论中 / 已接受 / 已完成 / 已放弃
- 负责人：
- 相关：Issue / PR / 原型路由

## 1. 要解决的问题（为什么现在做）
## 2. 范围：做什么 / 不做什么
## 3. 用户流程
## 4. 规则：状态机表、权限、限额（会写进 web/js/domain/<id>.js 与单测）
## 5. 数据：新增集合与字段（对应 docs/data-model.md）
## 6. 接口：方法 · 路径 · 入参 · 返回 · 错误码
## 7. 隐私与安全：哪些字段公开、哪些受限、审计什么
## 8. 复杂度预算自查（docs/engineering.md §6）
## 9. 待决问题（附建议）
## 10. 工作量、分工与风险
```
