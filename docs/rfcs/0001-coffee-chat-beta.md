# 0001 Coffee Chat 内测活动

- **状态**：讨论中 —— 可点击的原型已完成；上线范围与一周排期见 [PRD](../prd/coffee-chat-launch.md)
- **负责人**：待会上确定（写进 `.github/CODEOWNERS`）
- **原型**：`#/coffee`，代码在 `web/js/{domain,api,modules}/coffee.js`；演示登录用任意 `@yale.edu` 邮箱 + 验证码 `000000`

## 1. 要解决的问题

平台的第一个"内测活动"（话术：**交互平台内测 · Coffee Chat 第一期**）：两周里，在校生和校友按对方公开的空闲时间，约一次 15 分钟的 coffee chat，线上或线下都可以。

它也是第一个按 [engineering.md](../engineering.md) 三层拆分搭建的模块，用来跑通"原型 → 真实后端"的整条链路；后面的模块照着做。

## 2. 范围

**本期做**（✅ 原型已实现，⬜ 上线前补）

- 报名资料：姓名；邮箱（取自登录，不手填）；身份（在校生 / 校友）；在校生填学段、项目、毕业年份，校友填目前工作、所在城市；兴趣爱好；诉求（学界求职 / 业界求职 / 交朋友，可多选）；见面地点（线下店名地址，或线上会议链接）；首选联系方式（如微信）✅
- 空闲时段：活动两周、美东时间、每天 10:00–21:00，15 分钟一格、格间留 20 分钟（每天 19 格）；电脑上点选 / 拖选，手机上逐个点，点日期或时间整列 / 整行选 ✅
- 参与者总览：只按"身份""诉求"筛选，有空闲时段的排前面；点进个人页才看时段 ✅
- 预约：选对方一个空闲时段 + 一句留言（可选）+ 勾选免责声明 ✅
- 确认：被约人接受或婉拒；到开始时间仍未确认 = 不见面；无论接受还是婉拒，发起人都收到通知 ✅
- 接受之后：双方看到彼此的邮箱、联系方式与线上链接 ✅
- 通知：站内通知 + 未读角标 ✅；同样三个时机发邮件 ⬜
- 意见箱 ✅；管理员统计 ✅；所有写操作审计留痕 ✅
- 隐私说明与报名时的同意勾选 ⬜

**本期不做**：取消 / 改期（接受后用对方联系方式自行沟通）；被婉拒的时段重新开放；同步 Google Calendar、when2meet 式自由时间段、多时区；站内聊天；评价与爽约记录；推荐算法；提醒邮件（需要定时任务，见 §9 可选项）。

## 3. 用户流程

1. 用耶鲁邮箱 + 验证码登录 → 2. 报名填资料 → 3. 选出空闲时段 → 4. 在参与者里筛选，点进 TA 的页面选一个时间、留言、勾选免责声明 → 5. TA 收到通知，接受或婉拒 → 6. 接受后双方看到联系方式，按**被约人**的地点见面。

报名之前只能看到"活动介绍 / 报名 / 意见箱"；接口层同样拒绝未报名的请求。

## 4. 规则（已写进 `web/js/domain/coffee.js`，16 个单测逐条覆盖）

**预约状态机**

| 动作 | 从 | 谁可以 | 到 |
|---|---|---|---|
| accept 接受 | pending 等待确认 | 被约人 | accepted 已接受 |
| decline 婉拒 | pending | 被约人 | declined 已婉拒 |
| —（读取时计算） | pending，且已到开始时间 | — | expired 未确认 · 不见面 |

**时段规则**

- 一个时段只要被约过就不再开放，之后接受还是婉拒都不放出（简单、可预期；要改只动 domain 里一处判断）；
- 距开始不足 12 小时的时段不能再约（`cutoffHours`）；
- 同一时间一个人只能有一个进行中的约（无论约人还是被约）；两个人之间同时只有一个进行中的约；
- 一个人同时最多 3 个"等待确认"的预约（`maxPending`，防刷）；
- 已经被约过的时段，被约人不能从"我的时间"里撤回；
- 时段 id 是美东墙上时间（如 `2026-11-09T19:20`），换算绝对时间时处理夏令时；不在美东的用户额外看到本地时间。

**活动配置**（`web/data/coffeeEvents.json`，改日期只改这里）：`timezone`、`startDate`、`endDate`、`dayStart`、`dayEnd`、`slotMinutes`、`gapMinutes`、`cutoffHours`、`maxPending`。原型里的 11/2–11/15 只是占位。

## 5. 数据（真实版的表）

| 表 | 主要字段 | 说明 |
|---|---|---|
| `coffee_events` | id, name, timezone, start_date, end_date, day_start, day_end, slot_minutes, gap_minutes, cutoff_hours, max_pending | 一期一行 |
| `coffee_profiles` | user_id（主键）, name, email, identity, stage, program, grad_year, job, location, interests, goals[], meet_mode, meet_place, contact, slots[], created_at, updated_at | slots 内测期用数组即可，量大再拆表 |
| `coffee_bookings` | id, event_id, requester_id, host_id, slot, note, status, created_at, updated_at | **唯一索引 (event_id, host_id, slot)** 保证同一时段只能被约一次；状态历史另存 `coffee_booking_events`（= 原型里的 history） |
| `coffee_notices` | id, user_id, kind, booking_id, actor_id, slot, created_at, read_at | 写入的同时发邮件 |
| `coffee_feedback` | id, user_id, kind, text, created_at | 意见箱 |

另用平台公共表：`users`、`sessions`、`audit_log`。示例数据见 `web/data/coffee*.json`（全部虚构）。

## 6. 接口（12 条；原型 `web/js/api/coffee.js` 已实现，"关于"页自动列出）

| 方法 | 路径 | 说明 | 主要错误 |
|---|---|---|---|
| GET | `/coffee/me` | 活动配置、我的报名资料（未报名为 null）、待确认数、未读通知数、是否管理员 | — |
| POST | `/coffee/profile` | 报名 / 修改资料；邮箱取自会话 | `invalid` + fields |
| POST | `/coffee/availability` | 保存空闲时段 `{ slots }`；已被约的时段自动保留 | `invalid` |
| GET | `/coffee/people?identity=&goal=` | 参与者总览 | `forbidden/not_registered` |
| GET | `/coffee/people/:id` | 某人资料 + 各时段状态（free / yours / busy / taken / closed） | `not_found` |
| POST | `/coffee/bookings` | 预约 `{ hostId, slot, note?, agree: true }` | `slot_taken` `too_late` `you_busy` `duplicate` `too_many_pending` |
| GET | `/coffee/bookings` | 我的预约（约人的 + 被约的）与最近通知 | — |
| POST | `/coffee/bookings/:id/accept` | 接受（仅被约人） | `wrong_role` `expired` `invalid_state` |
| POST | `/coffee/bookings/:id/decline` | 婉拒（仅被约人） | 同上 |
| POST | `/coffee/notices/read` | 通知全部已读 | — |
| POST | `/coffee/feedback` | 意见箱 `{ kind, text }`（登录即可，不必报名） | `invalid` |
| GET | `/coffee/admin` | 统计 + 意见箱（仅管理员，查看也记审计） | `forbidden` |

返回格式与错误码见 [engineering.md §4](../engineering.md#4-接口约定)。另有一条 `POST /coffee/_demo/incoming` 只在原型里用来"模拟有人约我"，不属于契约。

## 7. 隐私与安全

| 谁能看到 | 字段 |
|---|---|
| 所有已登录的参与者 | 姓名、身份、学段 / 项目 / 毕业年份或工作 / 城市、兴趣、诉求、线下见面地址、空闲时段 |
| 预约被接受后，只有这两个人 | 邮箱、首选联系方式、线上会议链接 |
| 管理员 | 汇总统计与意见箱；不提供浏览联系方式的入口；查看本身记审计 |

- 线下见面请选咖啡店、图书馆等公共场所（已写进表单提示）。
- 上线前补：报名时的隐私说明与同意勾选；活动结束后数据保留期限（建议 90 天后删除报名与预约数据）；删除申请（内测期由管理员手动处理）。
- 参与者里有在国内的校友：隐私说明里写清收集目的、范围、存放地点（建议内测期数据放美国）与删除方式，满足《个人信息保护法》的告知与最小必要要求。

**换算成日历时间**

**风险**

1. **邮件进垃圾箱**——第一周就用正式发信域名发到 yale.edu 实测；登录页提示"没收到请查垃圾箱"。
2. **校友参与度**——招募比开发更难：先邀请种子嘉宾，强调"线上 15 分钟、开 2–3 个时段就行"。
3. **撞期**——期中、感恩节、期末；开发拖过 10 月底就整体顺延到春季。
4. **爽约**——免责声明 + 接受后交换联系方式；意见箱收集反馈，第二期再考虑"爽约记录"。
5. **审核瓶颈**——所有 PR 都要维护者审核；拆小 PR，约定 48 小时内回复。
