# 愿景与定位 / Vision

## 一句话

**Yalelux 是属于耶鲁人自己的社群平台：以 yale.edu 邮箱为信任基础，把校友的经验与资源沉淀下来，让活动走到哪儿都能组织，让学联的运营稳健可交接。**

## 我们要解决的问题

| 现状 | 问题 |
|---|---|
| 微信群是默认社群 | 圈子封闭：新人进不来，老人退群就断；信息刷屏后不可检索 |
| 经验靠口口相传 | 学长学姐在学习、生活、求职上的经验没有沉淀；每年新生在群里重新问一遍租房、银行、签证 |
| 资源散落 | 校招信息、内推、创业资源分散在几十个群与个人的微信里，无法精细化链接 |
| 活动靠人 | 学联办活动的流程、供应商、赞助商联系人存在某位部长的脑子和微信里，换届就丢 |
| LinkedIn 太泛 | 能建 connection，但没有耶鲁语境、没有中文语境、没有"我能帮什么"的精细标签 |

## 为什么是"邮箱信任圈"

- `@yale.edu`（在校）与 `@aya.yale.edu`（校友）邮箱是现成的、学校背书的身份凭证；
- 只需要验证码，没有审核成本，也不需要维护一份"校友名单"才能启动；
- 在此基础上，校友目录、内推请求、联系人库才敢开放——大家知道对面一定是耶鲁人。

## 两张面孔

1. **对外：校友社群生态平台**。用户是所有耶鲁在校生与校友。内容是职业发展、活动、子社群、创业、生活指南、校友目录。发帖属性 + 活动属性，像一个有身份的内部论坛。
2. **对内：ACSSY 学联活动后台**。用户是声明并（真实版）经审核的学联成员。内容是活动项目看板、SOP 库、联系人沉淀、沟通模板、志愿者招募。目标是**学联稳健运营、快速交接**。

两者通过"我想办活动"工作流连接：任何人都能发起社群活动；学联成员选一份 SOP 发起官方活动，系统生成任务，负责人分配、部员认领并反馈进度，活动页对外招募志愿者，公告推送给全体成员与相关子社群。

## 启动策略：职业发展先行

职业发展是最容易启动、价值最直接的模块：

- 校招信息与内推：把散落在群里的信息集中，标注"谁能内推"；
- 求职时间线：各行业的节奏由校友维护，新人一眼看懂；
- 简历工坊：修改案例沉淀成教材，愿意帮看的校友有标签；
- 求职小组 & mock：按行业组队，固定节奏，校友旁听；
- 行业研究：校友分享观察，建立在耶鲁社群里的影响力，同时拓展 connection。

职业发展部把这套流程跑通后，同样的"发帖 + 活动 + 目录"骨架可以复制到创业（Tsai CITY 资源与匹配）、生活指南、子社群。

## 设计原则

1. **基底优先**：先把模块注册、数据、双语、鉴权做成清晰的基底，功能由社区往上加。
2. **数据即文件**：原型阶段所有内容是 JSON，任何人都能改；真实后端只替换数据源。
3. **零依赖、国内可达**：不用境外 CDN，纯静态可部署到任何对象存储。
4. **经验要回流**：每场活动结束后复盘写回 SOP；每条指南标注维护人与核实状态。
5. **真实身份、克制的公开**：目录只对已验证用户开放；联系方式需同意后交换；联系人库只对学联成员开放。

## 不做什么

- 不做另一个微信：不做即时聊天，群聊仍然留在微信，平台负责"沉淀"与"组织"。
- 不做公开社交网络：没有耶鲁邮箱就看不到内容。
- 不替代学校官方系统（OISS、Yale Health、Handshake），只做指南与链接。
