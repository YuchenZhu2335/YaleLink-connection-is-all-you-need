# PRD：Coffee Chat 第一期上线（10 月 15 日）

- **状态**：待确认（确认 §8 的决策后按 §7 分块开发）
- **目标**：10 月 15 日前上线一个能真实使用的网站，开放第一期 Coffee Chat 报名；第一块是**注册**。
- **基础**：规则、接口契约与界面已在原型中完成（[RFC 0001](../rfcs/0001-coffee-chat-beta.md)）；本 PRD 只定义"从原型到上线"要做的事，并把范围压到一周能完成。
- **开发分支**：原型与上线开发都不在 `main` 上进行；上线版本审核通过后再合并。

## 1. 一周能上线的前提

原 RFC 估算 15–21 人日、4–6 周。压到一周，靠三件事：

1. **范围只留 P0**（§2）：上线的网站只有 Coffee Chat、隐私说明和关于页；其余演示模块（职业、活动、学联后台等，数据是虚构的）在上线环境隐藏。
2. **基础设施全部用托管服务**（§5）：不自己运维数据库和邮件服务器。
3. **代码主要按 PRD 生成，同学负责审核、部署、测试和招募**：业务规则和 12 条接口已经写好并有测试，后端主要是"接上数据库、登录和发邮件"。

做不到其中任何一条，就把上线日推到 10 月 22 日，而不是砍掉测试或隐私页。

| 优先级 | 功能 | 说明 |

## 3. 功能需求与验收标准

### 3.1 注册与登录（第一块，最先完成）

**流程**：输入邮箱 → 收到验证码邮件 → 输入验证码 → 勾选隐私说明 → 进入活动报名。

| 规则 | 要求 |
|---|---|
| 允许的邮箱 | `@yale.edu`、`*.yale.edu`、`@aya.yale.edu`；**服务端**校验，前端校验只是提示 |
| 验证码 | 6 位数字；10 分钟有效；输错 5 次作废；60 秒内不能重发 |
| 限频 | 同一邮箱每小时最多 5 封；同一 IP 每小时最多 20 次请求 |
| 会话 | 登录成功后发 httpOnly + Secure + SameSite=Lax 的 Cookie，30 天有效；可退出登录 |
| 身份 | 默认 `aya.yale.edu` 为校友、其他为在校生，用户在报名资料里可改 |
| 隐私同意 | 首次登录必须勾选；记录同意的时间和隐私说明版本 |
| 审计 | 发码、登录成功、登录失败都记日志（只记邮箱的哈希和结果，不记验证码） |

**验收**：
- 用真实的 yale.edu 邮箱能收到验证码（收件箱，不在垃圾箱），10 秒内到达；
- gmail 等非耶鲁邮箱被拒绝，并有清楚的提示；
- 关掉浏览器再打开仍是登录状态；退出后需要重新验证；
- 连续输错 5 次后需要重新发码；
- 数据库里看得到用户、同意记录和审计日志。

### 3.2 活动报名、时间、浏览、预约、确认

按 RFC 0001 §2–§4 与原型行为实现，规则不变（`web/js/domain/coffee.js` 原样复用）。上线时补：

- 预约成功、接受、婉拒时各发一封邮件，邮件里带网站链接，不带对方的联系方式（联系方式只在网站上、登录后可见）；
- 同一时段被两人同时约：先提交的成功，后提交的看到"这个时段已经被约走了"。

**验收**：两个真实账号完成"报名 → 开放时间 → 预约 → 接受 → 互相看到联系方式"，全程邮件到达。

### 3.3 管理员

- 管理员名单写在服务器环境变量 `ADMIN_EMAILS`，不在页面上设置；
- 能看：报名人数、在校生 / 校友、开放时段数、预约数与各状态、接受率、诉求分布、意见箱；
- 不能看：任何人的联系方式；
- 打开管理页本身记审计。

### 3.4 上线环境隐藏演示内容

- `config.js` 增加"上线模块名单"，上线环境只显示：约咖啡、关于、隐私说明、登录；
- 首页改为 Coffee Chat 活动首页；
- 演示验证码、"模拟有人约我"按钮、虚构参与者在上线环境一律不出现。

## 4. 非功能要求

| 项 | 要求 |
|---|---|
| 安全 | 全站 HTTPS；所有写接口校验会话；接口返回只含该用户有权看到的字段（原型 DTO 原样实现） |
| 隐私 | 收集最少字段；参与者包括在国内的校友，隐私说明写清数据存在美国、活动结束 90 天后删除、发邮件可申请提前删除 |
| 国内访问 | 用自有域名，不用 `*.vercel.app`、`*.onrender.com` 这类在国内常被屏蔽的子域；页面不加载境外 CDN（已是如此）；上线前请在国内的同学实测 |
| 可用性 | 预计 100–200 人，单台小服务器足够；数据库每日自动备份 |
| 审计 | 所有写操作、登录、管理员查看都记 `audit_log` |
| 浏览器 | 手机 Safari / 微信内置浏览器 / Chrome 都能完成全流程 |

## 5. 基础设施：需要准备什么

| 项 | 建议 | 费用 | 需要谁做 |
|---|---|---|---|
| **域名** | **不注册 yale 字样的新域名**，用 ACSSY 已有域名的子域名，例如 `coffee.acssy.org`。理由见下 | 0 | 能管理 acssy.org DNS 的人 |
| **服务器** | 一台美东的小型云服务器（1–2 核、2 GB），Docker 部署，同一个域名下同时提供网页和接口 | 约 $6–12 / 月 | 你开账号，绑卡 |
| **数据库** | 托管 PostgreSQL（如 Neon 免费档，美东区），自带每日备份；不在服务器上自己装 | 前期 0 | 你开账号 |
| **发信** | 事务邮件服务（如 Resend、Postmark），发件人 `noreply@coffee.acssy.org`；在 DNS 加 SPF / DKIM / DMARC | 前期 0（每月几千封以内） | 能管理 DNS 的人 |
| **代码与部署** | 本仓库新增 `server/`；推到上线分支后自动部署 | 0 | 我写，同学审核 |

**为什么不用 yale.edu 地址或带 "yale" 的域名**

- `*.yale.edu` 子域由 Yale ITS 管理，需要以注册学生组织的名义申请，一周内拿不到；
- 自行注册含 "Yale" 的域名可能违反耶鲁的名称与商标使用规定，学生组织一般只能写成 "at Yale"；
- `config.js` 里已经写着 ACSSY 的域名 `acssy.org`，用它的子域名最快，也最名正言顺。如果 acssy.org 不在学联手里，再买一个不含 yale 的域名（如学联英文缩写），约 $10–15 / 年。

**数据库前期需要的表**（9 张）：`users`、`login_codes`、`sessions`、`consents`、`audit_log`、`coffee_events`、`coffee_profiles`、`coffee_bookings`、`coffee_notices`；意见箱再加 `coffee_feedback`。字段见 RFC 0001 §5。

所有账号请用学联的公共邮箱注册，不要用个人邮箱，方便换届交接；密钥只放在服务器环境变量里，不进仓库。

## 6. 数据从原型到上线

- 原型的接口层已经支持两种模式：`apiBase` 为空时在浏览器里模拟，填上地址后请求真实后端；
- 后端直接引用 `web/js/domain/coffee.js`，规则不重写；12 条接口照 `web/js/api/coffee.js` 实现；
- 上线环境不加载 `web/data/coffee*.json` 的虚构参与者。
